1.3. PRODUCT OVERVIEW
Movie Booking Website is a centralized web platform allowing users to browse movies, check showtimes, select seats through a visual seat-map, and book tickets with online payment options (PayOS). Users can view booking history and manage accounts. Admins can manage movie listings, theaters, showtimes, bookings, and user accounts.
Front-end is built with React (Vite + Tailwind), backend with Node.js + Express, and database with MongoDB. Authentication uses JWT. Role-based authorization supports User and Admin portals. The platform aims to provide smooth booking experience with real-time seating availability and secure payment flows..
2. TEST PLAN OBJECTIVE
The primary objective of this test plan is to ensure the Movie Booking Website meets all functional and non-functional requirements. The testing process aims to identify defects within the booking flow, user authentication, and data management modules. Specifically, the goals are to verify that users can successfully book tickets without errors, ensure the integrity of the seat selection process (preventing double bookings), and confirm that administrative changes are reflected accurately in the user interface.
3. TESTING STRATEGY
The testing scope encompasses the entire application lifecycle, from user registration to the final booking confirmation. Functional testing will focus on the core business logic, including account management, movie search, seat locking mechanisms, and payment simulation. Non-functional testing will address the application's performance under load, security of user data, and compatibility across different web browsers (Chrome, Firefox, Safari).
3.1. System Test
System testing will verify the complete, end-to-end behavior of the system. Scenarios will be executed on the fully integrated platform to confirm that all components cooperate correctly.
Typical scenarios include:
* User registration and sign-in
* Browsing movies and selecting theaters
* Viewing and selecting showtimes
* Interactive seat selection and real-time validation
* Booking confirmation and record creation
* Viewing booking history
* Administrative actions (CRUD on movies, theaters, showtimes, users)

3.2. Performance Test
Performance tests will determine whether the system meets response time expectations under expected load. Simulated booking traffic will be used to measure performance for critical paths.
Performance focus areas:
* Seat-map rendering latency
* Simultaneous booking attempts on popular showtimes
* Payment confirmation responsiveness
* Dashboard query performance
Targets:
* Page navigation and seat map updates should remain responsive
* Booking confirmation and post-booking actions should complete without timeout
* System should handle typical peak load without degradation
3.3. Recovery Test
Recovery tests will force failures to ensure that the system maintains data integrity and returns to normal after failures.
Recovery testing includes:
* Browser refresh/disconnect during seat selection or payment
* Server restart during booking
* Payment cancellation or partial submission
* Database restart or temporary loss of connectivity
  Expected outcomes:
* No duplicate charges or double bookings
* Seat locking logic releases abandoned reservations
* Users can continue a booking where possible
* Database records remain consistent

3.4. Installation / Compatibility Test
The website will be tested to ensure it installs and runs correctly in supported environments. Testing will also check compatibility with multiple platforms and browsers.
Compatibility and installation checks include:
* Successful installation and deployment
* Correct configuration of environment variables
* Normal operation across supported browsers (Chrome/Edge/Firefox)
* Consistent display of seat map and tickets on different screen resolutions
* Support for deployment in development and production environments
General Testing Process Approach
1. Review functional requirements and repository documentation

3. Design test cases for core modules and edge cases
4. Prepare necessary test data and environments
5. Execute tests and collect evidence/logs
6. Record and prioritize defects
7. Perform regression testing after fixes
8. Compile the final test report

5.2. INSTALLATION TEST
Installation tests will validate that the Movie Booking System can be successfully set up, configured, and operated in the supported environments without malfunction. These tests ensure that installation procedures are followed correctly, required dependencies are available, and the system continues to function normally after installation or environment changes.
The installation test will include the following activities:
* Deploy the backend (Node.js + Express + MongoDB) and frontend (React/Vite) to the designated test environment.
* Verify that necessary configuration files (environment variables, database connection strings, API keys) are detected and applied correctly.
* Launch the web application in supported browsers to confirm that the system initializes properly and default routes render without errors.
* Validate that the application continues to operate normally while browser updates or Node package updates are occurring, ensuring that ongoing operations are not disrupted.
* Reinstall or update required runtime modules (Node packages, MongoDB services) and verify that the system resumes normal behavior after reinstall or update.
* Confirm that logging and error-handling modules are functioning as expected following installation activities.
* Confirm that uninstall and cleanup procedures (removing environment configuration files, clearing cached dependencies) do not leave residual data that would interfere with future deployments.
The overall objective of the installation test is to confirm that the system can be installed, upgraded, and recovered without corrupting data or impacting the functional behavior of the booking platform.
